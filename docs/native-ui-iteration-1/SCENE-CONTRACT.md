# Scene source candidate and validation boundaries

The local source includes additive typed `scene` blocks, input-form restoration checks, a public model-context relay and renderer lifecycle fixes. Existing tool inputs and historical resource aliases remain supported. Continuous native explanations remain self-contained; `render_response` supplies useful local visual aids and interactions.

A Scene combines immutable givens, bounded typed state, acyclic expressions, layouts, drawing marks and native controls. Every representation uses the same validated state. Invalid input keeps the last valid projection. Generic circle dragging has number, button and keyboard alternatives; cancellation discards the preview. Scenes do not add arbitrary code execution, external resources, persistence or automatic tool calls. Scene exploration is ephemeral: it is excluded from widgetState persistence and starts from authored values on a fresh mount without a host snapshot. Form/component restoration is a separate capability and does not promise Scene history restoration.

Valid exploration changes can replace this View's supplementary context through negotiated `ui/update-model-context`. Snapshot, block and interaction identities constrain updates; presentation state and private Quiz grading are excluded. Acknowledgement means host receipt, not next-turn adoption. Missing capabilities, denial or timeout preserve local interaction and report the synchronization boundary. Authoring guidance asks why questions to retain their topic and referent; this is not evidence of model memory. Current-condition answers require matching available context. The fixed synthetic v2 host card disables model-context synchronization and cannot establish this product-level capability.

The six tools use four primary resources: `document-v4`, `response-v7`, `renderer-v5` and `explanation-v4`, under `ui://chatui/` with `.html` suffixes. Sixteen historical aliases remain readable. Default generated resources have startup and entry diagnostics disabled. Optional developer diagnostics require explicit build flags and do not add a default diagnostic tool URI.

Local tests, synthetic previews and archive consistency checks do not establish real ChatGPT host acceptance. Historical first-load, refresh and native-message observations remain recorded. The user confirmed manual loading of the current synthetic product card and attributed the earlier failure to network loading; root-cause investigation has stopped at the user’s request. That manual-load confirmation alone does not validate other tools or host capabilities; the later per-tool scope is recorded below. Historical duplicate native prose remains a separate record. The user's G05 section navigation, focus and complete-copy acceptance is retained. Synthetic preview explanations are prewritten and context acknowledgements are simulated.

Historical deployment identities, screenshots, logs and private diagnostic packages are retained locally and excluded from public source packages. The historical `GENERATIVE-VIEW.md` record in a full repository checkout is not shipped in these packages. Local Git integration does not publish or change a deployed Site. See the [renderer contract](../../renderer/RENDERER.md) and [bundled third-party notices](../../renderer/gallery/THIRD_PARTY_NOTICES.md).

## Finite release candidate support contract (2026-10-26)

| Capability | Existing production behavior | Fixed v2 adapter / acceptance method |
| --- | --- | --- |
| Content | Six tools: render_html (sanitized HTML), render_response (typed Scene/structured view), render_document (Markdown/math/directives), render_component, render_explanation, render_incline_forces | v2 only accepts render_html({}) and returns one fixture. Test production schemas and normalizers with public synthetic inputs. The model authors content; the renderer has no separate content-generation model backend. |
| Layout / controls | Validated shared state, bounded expressions, SVG, controls, disclosures/tabs, pointer and keyboard alternatives | Check independent blocks, 320/360px, drag cancellation and keyboard alternatives on production resources; fixed-card evidence has a limited scope. |
| Copy | Current public exploration or complete safe fallback; denial exposes readonly text; stale callbacks cannot override current UI | Local denial/reentry tests and real-host behavior where available. A success label does not prove exact clipboard content. |
| History | Host widgetState may restore matching form/component/disclosure snapshots; changed identities reject old state | Real host save/reopen required. Scene exploration remains ephemeral; persistent Scene history is not implemented. |
| Model context | Negotiated ui/update-model-context sends bounded public replacement context; ACK means receipt, no automatic tool/model call | v2 disables it. Need host capability, real receipt and a separate next-turn check without disclosing the same value in native text; otherwise causality is unproven. |

Minimal production acceptance adaptation: reuse renderer/lib/mcp.mjs handleMcp with the existing owned loopback/admission lifecycle; advertise its six schemas and exact resource hashes, accept public synthetic HTML/Scene/Document inputs, preserve validation/budgets/CSP/authentication. Do not forward untrusted platform identity headers or add persistence/model capabilities. Changing the live App from its fixed schema to these six schemas needs an explicit tool-scope decision before refresh/discovery; offline tests do not authorize that change.

Finite host checklist: bind current production build/resources; exercise synthetic HTML, Scene and Document through their real tools; verify controls/narrow layout/copy/cancellation; test matching form/component save/reopen if host supports it; test negotiated context receipt and separately observe model adoption without native value leakage. Each result is independent. Host-unsupported capabilities stay documented limitations; persistent Scene history, if required, needs a product decision instead of a mock PASS.


Production authentication boundary: handleMcp rejects tools/call without the Sites-injected oai-authenticated-user-id and oai-authenticated-user-email headers. The official Tunnel runtime key authenticates the control plane, not a Sites visitor; the fixed adapter's synthetic admission is a third, separate boundary. A real production acceptance route must use trusted Sites dispatch, or a separately approved isolated synthetic-only test adapter with a fixed non-user test principal and explicit restrictions. Never trust caller-supplied identity headers or describe such a synthetic principal as production user authentication. An existing fixed live App cannot be silently converted to this route; the isolated six-schema route recorded below was subsequently approved explicitly.
