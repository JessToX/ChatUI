# 宿主能力与呈现边界

本参考用于第一次制作富视觉、需要真实控件，或判断用户提供的视觉参考能否复现时。依据当前工具说明、宿主文档和实际调用结果判断，不凭产品名称推断能力。

## 从视觉需要到实际调用

普通回答默认调用 `render_html`，包含正文、写作、译文、代码、静态表格和原生折叠；测验、图表、实验、有状态组件及复杂公式整轮调用 `render_response`。先确认本轮实际可用入口，不以 Connected 或目录刷新替代会话工具注入。`render_component`、`render_explanation` 仅兼容旧调用；专项光滑斜面计算保留其严格适用条件。明确纯文本和简单确认例外，不可用或修正一次仍失败则完整文字兜底。统一图文在透明视图内部排列；宿主决定 iframe 位置。工具返回不是可见渲染成功的证明。

先检查当前环境列出的相关技能与工具。若提供 Visualize 或其他适用可视化能力，读取其现行说明，并读 [组件制作](components.md)，按当前数据生成适用组件后通过该通道展示。随附模板是制作资源；工具支持执行和嵌入才构成可用通道。图片任务调用当前图片搜索与展示能力。一次已确认的能力可在当前环境继续使用，不必每轮重复发现；换宿主或工具报错后重新判断。

不能把“尚未检查能力”当作“能力不可用”。相应能力未提供、实际调用失败或明确不支持所需输出时才回退；一种组件不可用不代表其他图像、图表能力也不可用。文字能说明事实，不足以成为放弃有明确理解价值的视觉的理由。

对于受力、几何和数值关系，按实际可用能力依次判断：交互图形通道 → 可计算的静态图及内嵌图片通道 → 文字力表与方程。这个顺序不要求调用不存在的工具，也不要求为一张无需交互的图先尝试交互。只有 HTML/JavaScript 不可用时，继续使用已经提供的 Python/绘图能力；受力图的 [静态适配器](../scripts/render_force.py) 可输出 PNG/SVG，默认 PNG 更适合图片展示。执行器没有 matplotlib 时记录实际缺少的依赖，再使用其他已提供的绘图工具；不要要求用户复制代码来完成普通问答。

## 按实际能力选择

| 当前可用能力 | 合适的做法 |
| --- | --- |
| 普通聊天 Markdown | 承担正文、推导、短答和连续写作；视觉能力缺失时承接可读回退。 |
| 原生图表或可视化工具 | 用该工具制作需要图形表达的部分，并在聊天正文解释关键发现；遵循工具自身的输入与展示规则。 |
| 计算执行器与静态图片展示 | 用真实数据生成 PNG/SVG，通过宿主实际图片输出机制嵌入解释；受力图可使用随附静态脚本。不能声称具有滑块、可选文本或可点击控件。 |
| 可运行的嵌入式交互组件 | 用组件资源制作受力图、参数实验、分步推导、视角切换、资料筛选、图文排版、进度、时间线、比较、节奏、档案、结论与测验。按当轮数据选所需部分，保留主题、窄屏和键盘支持。 |
| 仅能创建独立文件或外部页面 | 只有该产物符合用户需要时才使用，并准确说明它会在哪里打开。不要将外部文件称为聊天内原生组件。 |

依照工具说明返回其真正支持的展示结果；调用记录或文字中的图片引用不单独证明客户端显示成功。无法观察客户端时如实保留不确定性。不要通过猜测内部接口、伪造工具名、特殊隐藏标记或猜测文件地址来触发渲染。普通回复中的任意 HTML、CSS 或 JavaScript 不等于可运行的组件。

组件制作代码交给执行通道，不在正常回答中要求用户复制运行。静态图片可用于图解，但不能当作有控件和可选择文本的 UI 验收结果。用户参考的外观指导组件内容与样式；宿主现行技术说明决定如何安全执行、传参和返回结果。

## 自动调用的真实含义

技能允许被支持它的宿主隐式选择，能指导被调用后的回答方式。技能正文中的执行约束在技能被加载后生效，不能反过来让尚未加载的技能自行启动。全局偏好应明确要求在相关任务中读取并使用技能，而不只要求模仿它的风格。实际是否被发现、是否在某轮加载、能用哪些工具，由宿主配置与能力决定。不要声称安装技能就能保证任何 ChatGPT 版本的每轮回复必定自动加载，或新增原本不存在的原生 UI 能力。

当用户询问为什么没有出现预期组件时，说明已知的具体缺口，并给出当前可用表达。例如：“这里可以直接显示公式和表格；这一轮没有可运行测验组件，我会用编号作答并在你回答后判分。”无需每次回复重复能力声明。

诊断自动显示问题时分开记录：技能是否被加载、资源是否读到、工具是否成功执行、结果是否在客户端可见。没有加载记录时写“无法确认”，不要由文字答案推断技能一定没被调用；工具调用成功但画面空白，也不能记为显示成功。更强的技能措辞不会自行创造调度钩子，修复应针对实际失败阶段。

## 真实交互

- 按钮、单选框、滑块只有在宿主支持可执行交互并已实现行为时才作为控件呈现。不要用按钮外观、假链接或勾选符号暗示已经接入功能。
- 原生交互内可完成的计算与展示，在组件内提供即时反馈。需要模型继续讲解时，使用宿主已提供且说明清楚的对话衔接方式。
- 如果控件无法把事件传回模型，不声称模型知道用户的选择。可在组件中显示结果，再让用户用正常消息继续。
- 有适用交互能力且操作能帮助理解时，实际制作并验证反馈；仅需一句回答或控件不可用时，使用清楚的文字问答，用户回复后判定并继续。
- 用户未操作前，不显示“已完成”“全部正确”或预填选择。发生工具错误时保留已完成内容，用简单形式继续，避免为了外观重复失败调用。
