# 受力分析与物理图解

“分析受力”“为什么有摩擦力”“斜面上怎么列方程”等任务自然触发图解；题目、对象和条件充分时直接制作，不让用户另发画图口令。按 [组件制作](components.md) 使用当前宿主的真实展示通道。先判断物理模型；通用组件负责已核对数据的呈现与向量运算。已知质量/g/角度的静止光滑斜面、仅重力和支持力时，优先使用 `render_incline_forces` 解析计算入口，直接输入题设参数，不手填支持力分量。

## 从题目到图

1. 确定研究对象和参考系，只列作用在这个对象上的真实外力。相互作用的另一方所受反作用力不画进同一对象图。重力、支持力、张力、摩擦等按题设判断；合力、分力、向心力不是另添的独立外力。
2. 判定方向。重力竖直向下，支持力垂直接触面，绳张力沿绳。动摩擦反对接触处的相对滑动，静摩擦反对相对滑动趋势；没有足够条件时保留未知，不能一律说与物体速度相反。支持力不总等于重力，静摩擦不总等于 μN。
3. 以全局向右/向上定义 `fx, fy`。斜面向右上升 θ 时，局部 +x′ 沿斜面向上，`axisAngle=θ`；局部 +y′ 为其逆时针正交方向。正文、图表、分量、方程都用一致坐标。不要把沿斜面分量当作全局输入。光滑、无其他力时支持力为 `mg cosθ(-sinθ,cosθ)`，必须垂直于平面；合力在法线方向的分量必须为零。检查正交约束与大小，不能仅因力的大小正确就认可箭头方向。
4. 数值、单位和力的大小已知时用 `force-diagram` 数值模式；只知道方向、大小未知或只有符号量时用 `mode:"direction"`，传入从全局 +x 逆时针量的 `angle`。所有箭头等长并明确大小未知，符号大小留在正文/力表。连方向也无法确定时先给已知关系，必要时澄清缺失条件，不能捏造方向。
5. 将图放在受力判断附近。图中的编号对应力表，表格说明来源、方向、数值/未知量。正文随后解释方程及关键误区，不重复朗读整张表。长推导留在自然 Markdown 与数学排版中。

题目指定的质量、重力加速度、摩擦和角度必须共同进入图与正文的同一组计算。题给 g=10 时，不能让原生实验组件继续用内置 g=9.81。先核对该组件能否设置全部必要参数；不能覆盖这些默认值时，改用能接受明确向量/加速度的 ChatUI Renderer 或真实静态绘图。不能保留矛盾的图，再只在正文旁边解释差异。参数更新后重新画图；大小未知时仍画方向示意，不把力表代替方向图。

Renderer 已显示本题数值图后，沿用这组数据继续解释，不再重复附加同题原生实验。例如已按 m=2 kg、g=10、30°画好斜面受力图，就不再追加使用默认 g 的斜面实验。运动题同样遵守：初速度、加速度、时间、单位以及适用的质量、g、角度都来自当前题设。只有额外图要回答不同问题，且能显式传入并核对全部适用参数时才使用；无法保证参数的通用原生模板跳过。来源照片、解释不同关系的图表和持续正文不受此限制，不把整篇回答都改成 UI。

## 数值与交互

数值模式只适用于二维质点外力向量；不能表示刚体上的不同作用点、力矩或任意场景几何。默认只显示真实力，合力及所选力的分解通过实际控件打开。分解以虚线区别于真实力，且不会加入合力求和。

给定全局向量 `(Fx,Fy)` 与旋转角 θ：

- 局部分量 `Fx′=Fx cosθ+Fy sinθ`，`Fy′=−Fx sinθ+Fy cosθ`。
- 合力只等于真实力分量之和；合力为零时显示零，不画有长度的假箭头。
- 所有数值箭头使用同一比例；大差异可能使小力很短，保留数值表，不把小力人为放大。
- 用户改力的大小、方向或斜面角度时，重新判断相关支持力/摩擦/约束，再生成更新图；不要仅旋转坐标就声称物理场景已经更新。内容身份随题目条件变化。

示例：2 kg 物体在水平面向右滑动，取 g=10 m/s²，右拉力 6 N、左动摩擦 2 N，没有竖直加速度；真实力为 `(6,0),(-2,0),(0,20),(0,-20)` N，合力 `(4,0)` N，加速度向右 2 m/s²。所有这些是假设示例，不能自动成为用户题目的数据。

斜面示例：取重力 `(0,-20)` N、θ=30°，局部分量为 `(-10,-10√3)` N。它们是同一个重力的投影，不能再与重力一起计入真实外力。

## 展示不可用时

先确认当前宿主是否提供图解/可视化或静态绘图通道；有能力就实际制作和显示。只有没有可用通道或实际调用失败后才回退为 Markdown 力表、方向说明和方程。文字回退仍完成必要受力分析，但明确图形未显示；不要把 HTML 源码、字符箭头或表格记为交互 UI 已通过。

“只列方程”“本轮不要图”等格式要求优先。之后新的受力任务重新判断，不把一次文字要求永久沿用。缺少宿主传回的交互状态时，不猜测用户开过哪个开关；对话依据用户消息和真实收到的状态继续。

## 静态绘图适配：普通 Chat 有 Python、没有 HTML 执行时

无 HTML 执行通道不等于不能画图。当前宿主若能运行 Python 并显示生成的图片，直接使用技能内的 `scripts/render_force.py`，不等待用户再要求画图。它生成真正的 PNG/SVG 受力图，不需要浏览器，也不依赖 HTML 或插件截图。

1. 先完成上文的物理判断，再把当前题目的 `force-diagram` 配置保存为 JSON。沿用 `assets/component-examples.json` 的 `schemaVersion:1`、`contentId`、`type`、`title` 和 `data` 结构。数值模式必须有 `unit:"N"`、`body` 和 1–12 个真实力，每个力提供唯一 `id`、`label`、有限数值 `fx/fy`；只知道方向时用 `mode:"direction"`、`angle` 并省略 `unit/fx/fy`。`axisAngle` 仅改变分析坐标，不能代替重新求支持力等真实力。
2. 使用当前宿主已有的 Python 绘图环境执行，输出到可供本轮展示的工作目录。替换下面路径占位符，不把输出写入已安装技能目录：

   ```sh
   python "<ChatUI技能目录>/scripts/render_force.py" "<本轮工作目录>/force.json" "<本轮工作目录>/force.png" --theme dark
   ```

   浅色主题使用 `--theme light`；需要矢量导出时将输出改为 `.svg`。普通对话优先 PNG，默认 160 dpi。
3. 本轮确实解释合力时加 `--resultant`；本轮确实解释某个力的分解时加 `--components weight`（用当前真实力的 `id` 代替 `weight`）。默认只画真实力。合力为零不画假箭头；分力用虚线，永远不重复计入合力。未知大小模式不允许数值合力或分解。
4. 检查实际生成图片，用当前宿主的图片展示通道将它放到相邻解释处，并在正文继续推导。成功生成文件但没有展示出来，仍不能记为“图已在对话显示”。后续更改条件时重新计算并生成新图。

脚本从当前系统字体中查找能完整覆盖标签的字体，支持中文；缺少 matplotlib 或可用字体会给出具体错误，不自动联网安装，也不覆盖已有有效输出。输入里的未知量、字符串数值、重复力标识、非有限数和错误单位会被拒绝，先改正真实数据，不能用随意数值补齐。长力名称放在下方力表，图中用对应编号；所有数值箭头使用同一比例，方向模式明确注明“箭头等长、大小未知”。

这是静态绘图通道，只能验证图形是否生成、展示和正确。它不提供滑块/按钮，也不能证明普通 Chat 已自动选择技能或宿主已实现强制路由。若当前宿主连计算绘图和图片展示都未提供，才按上一节如实回退。
