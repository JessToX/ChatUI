# 完整的图文讲解示例

> 旧 `render_explanation` 兼容性参考。新实质性回答统一使用 `render_response`；以下组件和 diagram 块仍兼容，新样例见 [统一样例](response-examples.md)。

这些 JSON 是可直接传给 `render_explanation` 的完整参数，使用虚构或明确采用的教学数据，不是用户的项目记录。读取当前需要的一份，按真实问题替换事实、标签和关系，不机械复述示例文案。字段依据现行工具契约；示例可通过源码校验，自动选用和客户端显示需另行实测。

## 概念讲解：速度为零，加速度仍然存在

用户：“忽略空气阻力，取 g=10 m/s²，初速度20 m/s向上。为什么小球在最高点速度为零，加速度还在？让我看懂。”

选择 [学习快照](examples/learning.json)。先说明速度与加速度回答不同问题，再并列两条公式；推导最高点时间，切换上升／最高点／下降三个瞬间。最高点不画速度箭头，加速度仍向下。实验以相同 v0、a 和单位起始，固定说明与实时读数分开。原生正文只需衔接，例如：“切换三个瞬间，重点看速度箭头和加速度箭头怎样变化。”

“初速度改成30，其他不变”：重新算 topTime=3 s、duration=6 s、halfSpeed=15 m/s，更新 `facts.v0/topTime/duration/halfSpeed` 和 `contentId`，提交完整 blocks；g和a保留，相关标签通过引用同步。“只解释最高点”：聚焦该状态和关键公式，不重复完整实验。“一句话”：只用自然文字。

## 写作分析与方案比较：让注意力落在变化点

用户：“分析一个虚构的出发场景：依次收拾物资、说明任务、离开诊所、等待、装甲车出现、装车出发。比较信息优先与感受优先两种写法，当前重点是装甲车出现，可给一个短片段。”

选择 [写作比较快照](examples/writing-comparison.json)。档案只提供明确标为建议的方向；对照说明两种组织方式的实际差异，定性节奏呈现场景关注度，再给连贯短片段。`facts.focus` 同时进入档案和解释，节奏等级不伪装成测量百分比。原生正文无需再把两种方案抄一遍。

“重点改成等待中的犹疑”：更新 focus事实和contentId，将等待的 `emphasis` 改为 `focus`、装甲车出现改为 `moderate`，相应修改片段，再提交完整快照。段落、人物与设定不擅自换掉。“现在写完整正文，这次只要正文”：输出连续文字，不调用组合工具。“把一句改得更克制，给我看前后”：使用上一轮实际原句做局部比较，不编造修改前版本；一张 comparison 足够时回到单组件入口。

## 进展整理：两个阶段共用一个分母

用户：“帮我整理一个演示项目：共10章，6章成稿，其中3章核对。日期与具体章节名称没提供，想看清两个阶段和下一步。”

选择 [进展快照](examples/progress.json)。短正文解释包含关系，阶段条共用总量；时间线只列已知阶段和明确作为建议的下一阶段，未知日期省略。facts 中10、6、3及已核对的派生缺口只定义一次；不推出前六章／后三章或全书发布已完成。

“又成稿一章，核对不变”：drafted=7、reviewed=3、remaining=3，contentId更新，完整快照再次提交。“总量改成12”：total=12、remaining=5，其余已知数量不变，两个阶段分母与所有说明同步；不补造新增章名。“一句话告诉我瓶颈”：只回复一句。“现在只看阶段数量”：单个 progress 足够，用 `render_component` 实际值调用，不能给该入口传 facts占位符。

## 模板之外：带反馈路径的因果假设

用户：“我怀疑需求不清晰导致返工，返工又挤占澄清时间，形成循环。帮我画出这个待验证假设。”

选择 [因果回路快照](examples/causal-feedback.json)。矩形与箭头按当前关系构造，结构化 path 表达反馈回路；不套圆内三角形、步骤卡或一条折线。图的描述明确是假设，不把箭头或条长当测量证据。facts 复用节点文字；没有证据强度就不编造百分比。

“把需求变更频繁也加进去”：重新明确它与现有节点的关系，新增对应节点与箭头，再提交完整快照。关系未明确时先说明假设或询问影响方向，不能猜成已证实原因。这份示例展示通用图元能力，不把自由图解限制为这三个节点。

## 共同的交付检查

- 用题意决定视觉是否值得出现；不要先挑模板再改变题目。
- 共用 facts 保证引用一致，派生计算与证据仍需先核查。
- 新条件用新 contentId与完整快照；原生正文不会更新旧卡。
- 图文穿插发生在透明 Renderer 内，原生正文只补充衔接。
- 真正观察显示、标签、控件和数据，不把本地 JSON 校验当普通 Chat验收。
