# 视觉与交互模式

把形式交给内容决定。以下是选择标准，不是每轮必须填满的模板。有结构或操作价值时按宿主能力实际制作；确认能力缺失或失败后再采用回退。短答和连续正文保持自然。

## 共同视觉方向

用户提供的参考决定外观。未另指定时，采用 [组件制作](components.md) 中的细边框、正文同色背景、适度圆角、数字层级和鲜明的蓝绿橙强调色；与普通段落共享阅读宽度。颜色在同一图表中保持固定含义，同时提供文字标签；中性背景和正文让重点清楚可见。正文负责论述，组件突出值得看见的结构。

不要为了追求视觉效果改变用户的内容含义。不能把“建议”画成“已完成”，不能把“未知”用空白图形隐藏。窄屏下并列内容改为纵向，长公式和长表格保持可读。

## 何时用什么

| 内容需要 | 实际动作 | 能力不可用时的回退 |
| --- | --- | --- |
| 受力分析、摩擦方向、斜面分解 | 读 [物理图解](physics.md)，制作受力图，按需开关分力与合力，紧邻力表 | 受力表加坐标约定与方程；说明图形未显示，不冒充图解通过 |
| 空间位置、几何或物理方向 | 调用绘图能力制作有标签的示意图 | 用精确文字描述关系与约束 |
| 数值趋势、参数对结果的影响 | 绘图；适合探索时制作数值与图示同步更新的控件 | 给关键数值及趋势解释 |
| 两个概念或等式两边的关系 | 制作并列比较，每边保留可读公式、名称与一句解释 | 短表格或分段公式 |
| 解题或操作的阶段顺序 | 制作步骤链，连线表达顺序，正文解释关键转折 | 有序列表 |
| 场景顺序、叙事节奏 | 制作结构或条形示意，标明编辑建议 | 场景列表与重点说明 |
| 多阶段事件与证据 | 制作时间线，附已知日期、事件和状态 | 按时间排列的列表 |
| 值得跟踪的完成量 | 用数字与可用进度组件说明进度口径 | “已完成 6/10”及口径说明 |
| 风格、人物或方案的稳定特征 | 制作档案，分清名称、定位、特征标签和解释 | 有层次的标题与段落 |
| 有区分度的练习或参数实验 | 制作有实际反馈的小测验或探索工具 | 编号题和选项，等用户提交后判分 |
| 实物、建筑或场景的外观差异 | 检索并展示真实图片，附来源与相邻解释 | 有效来源链接和可独立阅读的说明 |

两项对照、三步推导或一个完成比例也可能值得用一个紧凑组件，关键是是否让差异、顺序或状态更清楚。不要把“文字也能表达”当作取消视觉的理由；同样不为寒暄、确认或连续小说正文制造组件。

## 学习与公式

用图或对照突出关系，用文字解释为什么成立。数学公式保持可选择文本，并使用宿主支持的数学排版。推导中交代变量、已知条件与单位，重要等式之间写明逻辑，不把长串公式当作解释。

例如速度—时间关系，实际绘出坐标图来展示斜率与有符号面积，正文解释它们分别代表什么。用户改变初速度时，沿用坐标和单位更新对应图线与结果；不要只追加一张数值表而丢掉正在讨论的图形关系。

绘图前以最近用户确认的当前状态核对公式、图表数据、控件初值与结论一致；旧参数可作明确标注的对照，不能悄悄重新成为当前值。

例如讲解分离变量，制作“只含速度的左边”和“含时间与常数的右边”的并列公式组件，再用正文解释为何分别积分；核验后的最终结果可用紧凑结论组件。完整解题流程适合步骤链，每一步公式仍为可选择文本。几何图标出关键点、长度、角度和约束，图形比例与条件一致；非等比例图明确说明。

如果提供交互探索，优先以题给真实数值和单位初始化，并提供有效范围、复位行为与即时结果。组件范围无法表示原题时，换用能精确表示的能力，或用真实参数制作静态图；不能为了适配控件而随意改题。

若采用缩放示意，必须明确原题与示意之间的变量、时间及单位换算映射，并区分两套数值；不能仅标注“缩放版”就把它与原题当作同一实验。核对正文、图示、控件与计算在各自参数下保持一致。不能只有滑块外观而无数据变化；正文只有在可见结果或用户消息确认后，才引用用户改变过的参数，不猜测用户操作。

## 写作与叙事

用结构概览帮助看清场景顺序、视角变化、节奏或修订优先级。完整正文仍应便于阅读和复制，不把每段小说都拆成卡片。

叙事关注度属于编辑判断时，优先用“略写、适度展开、重点描写”等语言。需要条形示意时注明相对尺度，不伪装成测得的百分比或字数配额。提案、可选方向与用户确认的设定分别标明。

## 时间线、状态和进度

时间线只使用已知日期；近似时间写出“约”，缺失日期保留未知。事件来源、证据状态或仍待核实的部分在有必要时就近说明。

进度条必须有可解释的口径。已提供 6/10 章，只能表示“材料覆盖 6/10 章”，不能自动等同于翻译、审校或发布完成 60%。无法确定分母时用阶段状态或完成清单。

## 图表与小测验

图表标注变量、坐标轴、单位与必要的数据来源；示例数据直接说明是假设示例。定性判断不要绘制成未经支持的精确数值。

测验给清楚的题干和选项，避免先揭示答案，作答格式示例也不能含本组正确选项。用户作答后显示对错与理由；整组结束时根据真实答案计算成绩，并提供与错误相关的补充练习。可用的“继续”“重试”控件必须实现相应行为；文字模式使用正常对话推进。

有可运行通道时按 [组件制作](components.md) 实现选项、提交、逐题反馈和重试；总分由提交记录计算。组件内部结果可即时显示，模型后续解释只引用宿主传回或用户发来的记录。
